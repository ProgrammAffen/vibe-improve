# 金丝熊与恶龙的 3D 骨骼动画

- 日期：2026-10-14
- 状态：可行性与工具范围已核查，模型质量和绑定待实测
- 适用范围：H1 主页循环的制作源；后续皮肤与实时互动可复用
- 调研问题：能否将参考图中的金丝熊和恶龙分别转为 3D 模型，绑定骨骼后制作举盾抵挡喷火动画？

## 结论

**可以。建议用真实低多边形角色、骨骼绑定与 Blender 动画制作主页循环。** 这条路径可以明确控制举盾、屈腿、张嘴、翅膀、尾巴、光照与遮挡。最终是否达到参考画风，仍取决于模型外形、拓扑、权重、动画和灯光；图转 3D 不能省略这些检查。

制作源与主页播放分开：一期先由 3D 场景渲染出视频和 poster，同时保留可编辑 .blend、独立角色、武器、材质与动画。以后需要鼠标触发、换装或镜头交互时，再使用经验证的 GLB 和 Three.js。制作 3D 资产不意味着一期必须实时渲染整场景。

2.5D 是界面的视觉与镜头表达，可以用真实 3D 制作。固定三分之四视角、低多边形轮廓、柔和阴影与简化材质能保持参考方向；先比较透视镜头与正交镜头的静帧，以构图和角色比例决定，不预设严格等距投影。

## 工具能力与限制

以下为官方文档能力，未经本项目试用；生成商不设为唯一依赖，先比较同一角色的模型结果。

| 工具 | 已确认范围 | 本项目判断 |
| --- | --- | --- |
| Meshy 图转 3D / 多图 API | 支持图片建模；多图 API 接受 1–4 张同一对象不同角度的图 | 可生成模型候选；先独立角色与中立姿态，不输入整张战斗 UI |
| Meshy 网页绑定 | 文档支持人形与四足，复杂骨骼建议到 DCC 工具处理 | 可测试初始骨架，不能认定带翼龙的全身绑定完成 |
| Meshy Rigging API | 文档主要限定标准双足人形，不适合非人形或四肢结构不清的模型 | 不安排 API 自动绑定四足龙；网页能力不能当作 API 保证 |
| Tripo Studio | 官方说明提供双足/四足绑定、权重和预设动画 | 可比较四足基础绑定；翼、颚和异常比例仍需检查，不把预设动画当成抵挡龙焰动作 |
| Mixamo | 自动绑定与动画库针对双足人形，额外翼尾与夸张比例可能失败 | 金丝熊可作为实验，恶龙不依赖它；本项目无需接入才能完成制作 |
| Blender / Rigify | 有 Basic Human / Basic Quadruped 等基础 meta-rig，可定位骨骼并生成控制器；蒙皮另行完成 | 建议作为最终绑定、权重修正和动画制作环境；翼、颚、尾及披风按实际动作补骨骼 |

依据：[Meshy 多图 API](https://docs.meshy.ai/en/api/multi-image-to-3d)、[网页绑定](https://docs.meshy.ai/en/webapp/guides/3d-model/rigging)、[Rigging API](https://docs.meshy.ai/en/api/rigging)、[Tripo 动物绑定](https://www.tripo3d.ai/blog/ai-character-animations-animals)、[Mixamo FAQ](https://helpx.adobe.com/creative-cloud/faq/mixamo-faq.html)、[Rigify](https://docs.blender.org/manual/en/latest/addons/rigging/rigify/basics.html?highlight=pose+mode)。

## 参考图到模型

1. 分别准备金丝熊和恶龙的无背景角色参考，不含 UI、标题、火焰或另一角色。
2. 确认正面、侧面、背面与三分之四视图，保持同一比例、颜色、装备和细节。AI 补出的背面是设计补全，不是对原图隐藏表面的精确恢复。
3. 金丝熊采用便于绑定的中立 A/T 姿态；恶龙采用四足分离、翼与身体有间距、嘴部结构清楚的中立姿态。盾与剑独立建模，避免手臂被遮住或与武器焊成一体。
4. 生成模型候选，旋转检查腹部、背面、四肢、翼根、尾根和嘴内；修复缺面、粘连与错误形体。
5. 清理/重拓扑、UV 与材质，先做姿态弯曲测试。自动 remesh 或更多面数不能证明模型适合动画；肩、肘、膝、翼根等处须能正常变形。

图转 3D 服务的相关范围见 [Meshy 官方指南](https://docs.meshy.ai/en/webapp/image-to-3d)。服务和 API 的参数可能不同，实际使用时锁定支持的入口及模型版本；不将画风中的 low poly 等同于某个固定服务参数。

## 最小骨骼与附件设计

下表是本场景的设计建议，不是生成工具的默认产物。

| 对象 | 需要控制的部位 | 制作重点 |
| --- | --- | --- |
| 金丝熊 | 根、骨盆、脊柱、头、双臂、双腿；必要的手部与披风骨链 | 大头短肢使举盾更容易碰脸；手臂与腿部用 IK 或显式姿态控制，脚底接地，盾牌前倾受力 |
| 剑、盾、硬质护甲 | 独立刚性物体，连接手/前臂/躯干的附件锚点 | 剑盾不随蒙皮变软；装备部件不与身体不可分离地融合，为换装保留挂点 |
| 恶龙 | 根、骨盆/脊柱、颈、头、下颚、四条腿、双翼、尾骨链 | 四足基础加双翼，并非普通四足模板即可覆盖；翼根和翼膜、颈部弯曲、张嘴要专门检查 |
| 龙焰 | 嘴部发射锚点、盾面接触锚点与独立特效 | 火焰不作为角色蒙皮；跟随龙口，在盾前分流，暖光跟随喷火阶段 |

金丝熊先做抬臂、举盾、屈腿三个测试姿态，恶龙先做张嘴、转头、展开翼根三个测试姿态。外形和权重通过后再制作完整双角色场景，避免到最后才发现动作不可用。

## 动画与火焰

两个角色在同一场景、同一时基下制作：龙蓄力时熊先举盾，喷火时熊重心后移并保持脚底支撑，火焰停止后双方回到待机。固定相对位置和接触关系，不把两条无关的预设动作循环简单叠在一起。

约 8–10 秒周期，首尾变换、姿态、光照和速度连续；火星在边界消散或严格周期匹配。详细分镜继续使用主页设计（历史临时材料已清理：`../../tmp/review/2026-10-14-phase-1/11-home-loop-design.md`）。

优先用风格化火焰网格/曲线、发光材质和少量粒子，匹配低多边形画风。流体模拟可用于离线试片，但增加缓存、渲染和循环控制工作，不作为最低要求。火焰在盾面结束和扩散可直接按动画编排，不要求完整物理碰撞模拟。

## 视频与实时 3D 的选择

| 输出 | 适用行为 | 边界 |
| --- | --- | --- |
| 3D 离线渲染 → MP4 + poster | 固定主页循环；一期推荐 | 主页只解码视频，换装需另渲染版本；保留源工程避免资产只能当视频使用 |
| GLB → Three.js 实时播放 | 鼠标触发动作、实时换装、镜头变化 | 需要 GLB 动画验证、材质/特效实现、阴影、GPU/内存预算、上下文丢失与静态降级 |

GLB 可以携带角色骨骼与动画，但不是整个 Blender 场景的无损执行包。IK/约束的结果需烘焙并检查导出；材质节点、体积火焰、流体或布料模拟不能默认直接搬到网页。实时模式的火焰、动态照明和时序需要单独实现，视频模式则在离线渲染中固定。

导出后用目标加载器重新打开，检查静止姿态、每个 clip、装备挂点、材质、比例与循环边界；不能只看 Blender 内预览通过。Three.js 提供 [GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html) 与 [AnimationMixer](https://threejs.org/docs/pages/AnimationMixer.html)；导出范围见 [Blender glTF 说明](https://docs.blender.org/manual/en/3.6/addons/import_export/scene_gltf2.html)。这里仅引用格式的基础范围，实际导出选项以制作时锁定的版本验证。
