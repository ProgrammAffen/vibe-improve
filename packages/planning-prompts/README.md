# 内置规划提示词

本目录是 App 内置任务规则、响应契约和完整示例的唯一来源，源于 2026-11-04 审阅通过的统一规划方案。规则不按 provider 分支；生成时写入 Swift 常量，运行时不读取工作目录、用户文件或网络。

`interview / outline / lessons / review / consistency` 使用共同 envelope，`edit` 保留已有 `{reply,route}` 协议及 RouteV2 身份字段，以兼容现有编辑采用流程。公开 RouteV2 契约继续来自 `contracts/route.schema.json`；构建器只引用其可达定义，不另维护副本。

访谈默认四题，采集目标、达标表现、已有基础及每周时间；最多补问一个具体问题。旧题字段兼容，未完成的补充项不阻塞。访谈同次判断包含采用候选后的跨题一致性评估；独立 `consistency` 任务用于旧项目或采用同步建议后的生成前检查。输入使用已采用快照，保留本轮草稿作比较，不以草稿覆盖背景。非成功响应可提供结构化待复核事项；宿主核对目标题目、字段和实际快照，不从自然语言猜测。快照版本、事实哈希、epoch、采用事件与最终门禁由领域层管理，模型不生成这些可信元数据。旧访谈响应可缺一致性字段，届时须由宿主执行生成前检查。

总纲先写最终表现和达标证据，再安排先修、指导练习和独立应用。`practiceRules` 记录共用案例起点、比较基准、接口和参数。依赖具体前序产物的章节通过 `prerequisiteChapters` 标记直接依赖，细化在对应产物就绪后开始，并优先取得这些章节的公开练习内容。无依赖章节可并行。检查点保留约定与依赖，路线格式沿用 v2。`version` 标识提示词内容，`generationCheckpointVersion` 标识未完成生成的兼容边界。

独立题用不同于示范的输入。题面和公开达标条件提供解题所需数据和规则。判分参考结果、可接受解法与缺证处理写入 `evaluatorPrompt`，量化与定性均适用。语义审阅先按公开题面复算，再核对正确和典型错误作答的判定。学习页与生成预览只显示公开内容。依据见[公开提示词调研](../../research/learning-plan/2026-11-13.md)。

修改 markdown、schema 或示例后运行 `node scripts/build-planning-prompts.mjs`。`--check` 校验生成文件未漂移。每个请求只包含当前任务可达 schema、当前任务示例及必要的共同规则。保存前由 `review` 检查完整路线，并按需进一步定位无目标问题。修订沿用 `lessons` 契约，按审阅指定的小节分批修改，改名仅用于明确标记的小节。宿主逐批验证身份、范围和结构并保存到生成草稿，以最新候选复审。审阅用 `result.summary` 概括最主要的问题，修订使用具体证据。

访谈按需先解释含义、给出贴近主题的例子或建议，再问一个具体问题。新手无需提供专业知识清单。普通信息不足返回 `ok + complete=false`，解释在 `reply`，短追问在 `unresolved`；明确单建议后的同意可引用，多个选项后的含糊同意继续澄清。建议未经认可不能填为用户事实；所有充分回答仍须通过界面确认。

确认后可预采集下一题。宿主用 B 引用提供前面已确认题中的用户消息，保留每题首条及最近消息，总计最多八条。前文足够时返回待确认总结，信息不足时只问缺口。已有基础可附主题快选。B 引用不能关联旧助手建议，前文内容不写成当前题用户消息。

跨题检查先于本题确认。自然细化正常继续；不确定是否改动前文时留在当前题澄清，返回 `complete=false`。用户明确表达改动意图后，候选同时附上最小跨题建议，由当前确认卡片展示原值、调整后内容并统一确认。模型不能声称建议已经生效，也不能要求确认后自动跳回旧题。同步建议后的最终背景仍须重新检查。

构建器对可达契约执行受控词汇检查：未知校验关键字、未支持的类型、关键字值、非本地或缺失引用均阻止生成。新增校验能力时须同步 JavaScript 与 Swift 校验器并通过两者的共享用例；不能只在 schema 添加规则后让运行时忽略它。`$ref` 与同级约束共同生效。

示例仅使用合成数据。离线契约通过不等于模型遵循率、教学效果或新 CLI 集成已验证。
