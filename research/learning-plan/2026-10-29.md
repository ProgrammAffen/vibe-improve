# 职场学习计划的方法与信息采集

- 日期：2026-10-29
- 状态：方法依据可用；产品访谈、估时与学习效果待实测
- 适用范围：本项目成人自主学习、AI 辅助规划与路线编辑；不替代领域课程标准、资格考试要求或专业评估
- 调研问题：如何从个人目标和现状生成可执行、可检验、可修订的提升路线；哪些信息值得采集
- 方法：检索原始实验、元分析、官方研究报告、研究者模型网站与大学教学中心；核对摘要或可访问正文的研究对象与结局。不是预注册系统综述，不主张穷尽全部证据。

## 结论

**已确认的依据**：目标、任务与评价需要对齐；先备知识、学习材料和使用情境影响教学选择；检索、分散学习、示例与练习、具体反馈各有适用条件。自我熟悉感和完成作品不能自动证明独立掌握。

**设计推断**：采用“成果与标准 → 起点与差距 → 能力阶段 → 具体学习活动 → 时间与复现 → 用户审阅 → 实际表现校准”的生成流程。任何一篇研究都没有验证本 App 的整条流程或某个通用提示词的效果。

**产品选择**：沿用信息采集方案1的三组主入口，补充任务锚点、帮助条件、期限类型、工具条件等条件问题。章节验收仍可省略；练习建议不等于强制考试，用户自评完成不伪装为测试通过。

## 生成方法

以下是依据上述原则形成的产品方法，不是已验证的统一处方。

1. **把主题变成任务。** 例如“学Python”补成“读取、清理销售数据，做图并向业务同事解释变化”；明确成果、应用情境和暂不覆盖范围。先由用户确认目标，AI不能擅自把兴趣学习改成考试或就业承诺。
2. **约定成功的样子。** 对成果设可观察的质量条件及允许使用的帮助。能量化才量化，数值来自考试规则、真实任务、用户约定或可核实来源；不能凭空写80分代表掌握。用户不会定标准时由AI提案。这里的总体标准不要求每个小章都有正式验收。
3. **识别必要能力与起点。** 根据领域可靠资料或明确的任务分析列出先修能力及依赖；区分自述、作品、实际尝试、推断。必要时提供可跳过的短任务；拒绝诊断时以保守假设起步并保留调整，不伪造能力等级。
4. **按能力里程碑组织大章。** 每章有独立阶段目标及与小章目标的对应。章节数由能力增量决定，不按小章数量、页数、估时平均分配。复杂能力既要分项学习，也要安排整合与相关新情境应用。
5. **为小章设计学习活动。** 不只写“看视频”。按任务和基础安排示例、补步骤、独立尝试、解释、操作、反馈修正；需要辨别时安排对比练习。资料、活动、可选证据均能对应目标。较长整体任务可以跨多次工作时段，不因单次时长强行重划大章。
6. **分配真实预算。** 估时包含资料理解、练习、反馈修正、跨时段复现、整合成果和必要工具准备；标记外部反馈等待。时长给范围、估计依据和不确定项，首轮代表性任务后校准。没有时间信息仍可生成结构草稿，但不能宣称已经排出可执行日程。
7. **安排复现与使用。** 按目标使用时间、保持需要和实际回忆/应用表现调整。知识回忆、程序操作、沟通练习采用不同活动，不强制全部变成闪卡。复习占用同一周预算，不能额外隐形加课。
8. **审阅、执行和修订。** 用户可改范围、目标、章节、标准和日程；AI修改先提案。实际耗时、错误、帮助程度、延迟表现和场景应用比“觉得轻松”更适合校准。复盘与调度是设计机制，不是学习效果证明。

## 信息采集的最小集合

首屏维持“目标 / 基础 / 时间”三组。目标和基础允许“不确定，由AI协助”；可选问题按是否会改变路线触发，不一次要求填完全部档案。

| 层级 | 信息 | 对路线的影响 |
| --- | --- | --- |
| 基本 | 主题、目标任务或成果、实际用途 | 确定范围、内容和最终应用任务 |
| 生成前协拟确认 | 成果的成功条件、能使用哪些工具/资料/AI | 确定学习深度与证据解释，不强制小章考试 |
| 基本 | 具体先备任务、能独立/需提示/未做过/不确定 | 决定补哪些基础、跳过哪些重复、用多少示例支架 |
| 基本但可未知 | 可持续每周预算、单次时段长度或范围 | 决定活动规模与日程；未知只产出未排期草稿 |
| 条件 | 使用/考试/交付日期、硬期限或可调整、长期保持需要 | 判断可行性和复现窗口，不只追问结课日期 |
| 条件 | 必要工具/设备/软件版本、实操机会、预算和访问条件 | 剔除当前无法执行的活动，提出替代资源 |
| 条件 | 练习/验收可获得的反馈、受众或合作对象 | 区分AI建议、可验证结果和需要人际现场表现的证据 |
| 可选 | 已有资料、卡点、曾尝试的方法、想跳过的内容 | 去重和针对性练习；资料存在不等于已读或已掌握 |
| 可选 | 可用时段是否波动、常见阻碍、备用安排、语言/字幕需求 | 调整可执行性和呈现方式，不做人格诊断 |

不收集与路线无关的身份证、住址、薪资、雇主、年龄、性格测试或学习风格分类。尽量用合成/脱敏样例，用户主动加入的工作材料才进入指定Agent上下文；原始背景和对话不随路线分享。

## 预算与例子

假设用户确认每周4小时、6周内交付，可用总学习预算约24小时。若保留目标的计划估计为22–30小时，应显示存在超出风险，让用户选择缩小范围、调整期限或增加可用时间；不能把所有节点时长等比压到24小时后宣布可行。这些数字仅为产品演示，不是该技能的研究结论或统计置信区间。

同一目标也要区分条件：能在查文档、用AI时完成报告，不等于能闭卷解释方法或发现AI的错误。学习计划应尊重用户实际工作条件，不为追求“独立”而无理由禁止合法工具；观察证据必须描述当时使用的帮助。

## 验证方式与未确定事项

- 本次已完成来源与设计边界核对，未对本App进行学习效果实验、心理测量验证或估时标定。
- 后续用编程分析、语言表达、概念判断等不同任务的合成案例检查目标对齐、先修、预算、未知项和可选验收，再进行真实自愿试用。
- 分别检验访谈负担、草稿可执行性、估时偏差、实际任务表现、延迟保持与新情境应用；不以模型输出JSON成功、用户满意或金币量代替学习结果。
- AI评分的可靠性、跨模型一致性、主观任务评审和长期迁移需另行验证；无法提供支持证据时保留“未验证”。
- 领域教材、软件、考试与任务要求随目标另行核实；本报告不是任何具体学科的完整课程。
- 本轮不推荐固定复习序列、学习时段长度、学习/练习比例、章节数或统一通过率。SMART/Bloom等可辅助描述，不作为学习有效性的保证。

## 对开发的影响

采用上述规划原则并完善信息采集设计；详细交互、字段字典、生成约束和检查案例保存在本轮审阅目录。运行时尚未实现这些字段，不能把设计文档当作已上线功能。后续统一更新路线及准备契约、生产者、消费者、校验、版本迁移和恢复测试。

现有v1大章没有独立阶段目标，验收没有明确AI评判结构。不能只加表单而保存时丢字段，也不能给旧路线伪造已确认目标；迁移必须保留源数据与待确认状态。
