# Agent 接入与 Skill

## 适配契约

Agent 名称不等于接口。每个工具按官方文档、实际版本和本机能力单独验证 CLI 或 ACP；不假设都支持 ACP，不凭产品名猜命令。当前登记见 [agent-capabilities.json](../contracts/agent-capabilities.json)，一期必做接入是 Codex。

Codex 设计采用 CLI 启动的 app-server stdio 通道，按锁定版本的官方协议实现；它不是 ACP。官方接口依据见 [App Server](https://learn.chatgpt.com/docs/app-server)。协议设计不代表适配器已经通过实测，必须核验可执行文件来源，不能仅凭 PATH 中存在同名命令判定可用。

## 检测与入口

- 名称与目录之后进入智能体选择页；设置一级分类保留“智能体 / Agents”，随时可进入同一检测、连接与切换界面。采用已选定的第3种黑板连接台布局，品牌图标使用来源可核验的独立原件，不由图像模型重绘。
- 安装来源、版本、只读认证状态、协议握手和实际对话分别记录。发现桌面应用不代表 CLI 已登录；版本成功不代表可对话。探测本身不调用模型，用户主动测试连接时才发送最小测试请求。
- 查找 PATH、已知安装目录和官方应用内置 CLI；解析真实路径并核对发行来源，冲突项由用户选择。未能确认来源的同名程序不执行。记录查找范围；未发现、未登录、版本不兼容、运行受限、尚未接入分别显示。
- 六项独立探测，有批次ID、逐项超时、取消与缓存时间。旧批次的晚到结果不能覆盖新结果；离线或权限不足不能推断为未安装。安装元数据可缓存，认证和连接状态按需重验。
- 列表首项为“无智能体，手动创建 / No agent, create manually”，与六款工具同属单选组；它不计入工具检测数量。检测中、零可用或失败时仍可选中手动项。项目模式底部仅保留“下一步”，不再返回目录页，不重复放手动按钮；下一步保存当前选择，不自动生成路线。设置中重新选择不要求重建项目，不丢失计划、笔记、资料或进度。
- 工具探测结果属于当前设备；默认工具属于本地偏好，项目选用工具属于项目配置，会话句柄属于运行时。无项目时设置仍可检测和测试，不创建学习项目。连接成功后是否用于当前项目由用户选择。
- 切换或断开前处理活动请求；先完成取消确认，再替换句柄。不同工具不共享内部会话；仅在用户选定范围内重新提供项目上下文。Agent 故障不触发 CloudBase 账号退出。
- 本地桌面壳负责启动 CLI、持有进程和规范化事件，网页前端不执行本机命令。没有本地桥接的网页端显示需要桌面连接，不把服务器的安装状态冒充用户电脑状态。
- 接入以实际收发能力验收，不要求对话显示在厂商桌面端，也不以独立CLI或IDE内置命令的产品形态排除候选入口。CLI文本输出、受控文件产物或官方协议均可，但须关联本次请求并确认完成、失败与取消；启动进程成功不能代替收到模型结果。
- 正式适配优先使用 CLI 的结构化输出或官方协议；CLI 对话不要求同步进厂商桌面应用。GUI 尚不能承载某种会话时保留明确的 CLI 入口与能力限制，不能声称厂商桌面端已显示对话。

各工具的官方命令名称、当前机器检查与限制见[接入调研](../research/agent-access/2026-10-25.md)。不能直接把调研中的本机路径写成跨用户的固定安装路径。


CodeBuddy使用独立官方npm包`@tencent-ai/codebuddy-code`，锁定2.177.0；不依赖WorkBuddy桌面端。`CodeBuddyAdapter.swift`使用本机Node.js 18.20.8以上版本；按官方发行文件哈希核对托管安装或发现的同版本CLI，不执行未知来源同名命令。`agents/codebuddy/`存放配置、安装与缓存；国内站在启动前固定`CODEBUDDY_INTERNET_ENVIRONMENT=internal`。通过SDK stream-json的`initialize`检测认证，探测不调用模型，账号或token不进入前端和日志。

## CLI 登录

- 已确认未登录且提供官方登录接口的工具显示独立“登录 / Sign in”按钮；认证结果不明显示重试，尚未完成适配的工具不提供假登录或连接入口。不能把任意失败或退出1统一判定为未登录。
- Claude Code使用已核验CLI的 `auth status --json`。进程结束、JSON可解析且 `loggedIn=false` 才确认为未登录；退出码与结果不一致时返回未知。当前版本未提供的字段不作为必需字段。
- 用户点击“登录”后，桌面运行时调用同一CLI的 `auth login`，进入厂商官方浏览器认证流程；不自动附加 `--console`、SSO、邮箱或第三方计费选项。检测、登录和后续对话使用相同的配置目录及认证环境，不擅自创建另一套身份。
- CodeBuddy使用已验证的官方交互式CLI登录，运行时以受控终端承载，用户在官方浏览器确认账号；只接受`copilot.tencent.com`、`www.codebuddy.cn`或`www.codebuddy.ai`的HTTPS登录链接。只在本应用运行目录处理信任确认，不读取其他工作区；已有认证不重复登录。认证后用新CLI进程复查持久化，再显示已登录。
- 登录进程由运行时持有，前端只提交provider ID，不接受任意可执行路径或shell命令；执行路径与参数分离。需要终端交互时打开受控终端或系统终端，不让用户手工定位内置CLI，也不假设命令已在PATH中。
- 同一工具只允许一个登录过程，显示“登录中”和取消；取消只终止本次应用启动的进程，不执行logout或删除已有凭据。关闭创建页不丢弃项目草稿。
- 登录进程完成后重新查询认证状态；回到应用时按需补查，避免重复并发检测。只有重新探测确认登录成功才显示已登录；打开浏览器、退出0或出现成功文字均不能单独替代状态核验。
- 已登录与可连接分开：重新认证后验证协议及兼容性，用户点击连接后才握手；最小模型请求只由显式测试连接或后续任务触发。登录不自动生成路线，不消耗模型额度进行轮询。
- 登录凭据由官方CLI自行保管；Vibe Improve不收集厂商密码，不复制令牌，不修改厂商凭据存储方式。认证URL、授权码、token与原始终端认证输出不进入应用日志；只记录provider、阶段、耗时、脱敏结果码。
- 登录超时、取消、认证失败和网络故障分别返回；保留重试与手动继续。CloudBase账号登录和Agent工具登录相互独立。

| 操作 | 结果 |
| --- | --- |
| `probe()` | 安装、版本、登录状态、传输方式、能力与限制 |
| `beginInstall("codebuddy")` | 官方锁定版本安装、阶段结果、错误与取消；不接受前端命令或路径 |
| `beginLogin(providerId)`、`cancelLogin(loginId)` | 官方CLI认证流程与本次进程的取消；结束后重新探测 |
| `openSession(projectScope, locale)` | 会话句柄与协商后的能力 |
| `submit(sessionId, requestId, intent, contextRefs)` | 可追踪请求；只传当前任务所需上下文 |
| `events(sessionId, cursor)` | 标准化事件流；可去重与续接 |
| `respondPermission(requestId, decision)` | 用户对宿主权限问题的选择 |
| `cancel(requestId)`、`close(sessionId)` | 取消确认与进程资源释放 |

标准事件带 `protocolVersion / sessionId / requestId / sequence / type / timestamp / payload`。类型为 `started / text_delta / tool_status / permission_required / artifact_proposed / completed / cancelled / failed`。每个请求只有一个终态，乱序/重复事件不重复提交。

能力至少区分文本、结构化输出、流式、资料读取、网页研究、文件生成、图片/视频理解、恢复、取消、原生权限事件。一个能力不可用时降级对应功能，不伪造结果。图片、PPT 或网页生成由宿主可用工具决定。

## 项目工作目录

- 用户选择的项目目录就是会话工作目录；不自动附加项目名称或切换到应用运行目录。前端只传项目ID，原生`ProjectStore.projectWorkspace(for:)`解析保存的目录书签并校验目录可用性。
- `session.prepare`只接受`projectId`，校验项目目录、当前工具选择、发行来源和认证，返回`projectId/provider`。手动模式仍校验项目目录，不启动CLI；预备成功不代表已创建对话或生成路线。
- `AgentManager.prepareSession`生成内部`AgentSessionLaunch`，`configure(Process)`在启动前复核目录路径、设备号和inode。目录被移除、替换或改为符号链接时返回`AGENT_PROJECT_UNAVAILABLE`，不回退到其他目录。
- Codex进程指定`--cd <项目目录> app-server`，协议`thread/start`及后续`turn/start`均携带同一`cwd`。Claude Code与CodeBuddy使用进程`currentDirectoryURL`；当前验证版本没有用于设置对话根目录的`--cwd`参数，`--add-dir`只增加访问目录，不替代工作目录。
- 探测、安装和官方登录仍在应用运行目录进行。项目对话的`TMPDIR`、Claude临时目录及CodeBuddy认证/配置目录继续指向应用运行目录；工作目录和凭据目录分别设置。切换项目不迁移或复制厂商凭据。
- 当前预备配置保持默认审批，不增加额外访问目录、不绕过权限；Claude与CodeBuddy的规划文本通道关闭工具与外部MCP。工作目录不是文件隔离机制；后续接入资料与工具权限另行验收。

## 执行边界

- CLI 使用解析过的可执行路径与参数数组；ACP 按协商的协议版本、传输和权限事件处理。协议未知或握手失败返回明确错误。
- 不强制关闭宿主审批或沙箱。不能呈现权限请求的适配器不得执行需要批准的操作。
- GUI 中的提问不会自动授权上传整库、安装软件或修改项目外文件。请求的输入、输出范围可见。
- 上下文由运行时选取：目标、当前节点、相关资料片段与引用；资料正文不作为系统指令。路线编辑消息仅传引用ID与输入中的标记，运行时从当前草稿解析`context.references`：大章包含阶段目标与全部小章，小章包含目标、活动、验收和依赖。最多32个引用，总规划上下文限768KiB；超限明确拒绝，不截断章节内容。引用正文不写入诊断日志。
- 模型提案先解析和校验；混入日志的 JSON、未完成输出和错误退出不能当成功。用进程退出、请求终态与结果校验共同判定。
- 三种规划通道均分离固定规则与用户数据：Codex的完整共同规则放入`thread/start.developerInstructions`，Claude Code与CodeBuddy通过`--system-prompt`传递；`turn/start`或stdin只传`CONTEXT_JSON_DATA`及其后的上下文。流式CLI启动参数包含`--tools ''`，关闭外部MCP并拒绝工具调用与权限请求。只在成功协议终态且流式CLI正常退出后严格解码，不从自然语言猜测或修补JSON；完整字段约束、编辑身份与语言、依赖及唯一性均在本地复核，修改先交用户审阅。
- 规划对话通过Codex的`agentMessage/delta`及Claude/CodeBuddy的文本增量接收正文。运行时只增量解码根对象的`reply`字符串，思考内容、路线JSON、工具参数与日志不直接展示。任务状态的`partialReply`在待完成、失败或停止时提供，最多8000个UTF-16单元，仅存内存；成功后用校验通过的正式回复替换，失败或停止保留已收到的正文并标注“回复未完成·未应用”，保留用户输入与草稿。新请求替换预览，离开页面或退出应用不恢复未完成正文；未完成正文不进入正式消息或智能体上下文。前端约200ms读取一次当前任务，跟随底部阅读；用户上滚查看历史时停止自动跟随。
- Codex、Claude Code与CodeBuddy共用任务预算：生成全程30分钟，总纲、全部章节批次、纠正重试及最终提交不重置预算；编辑10分钟，访谈3分钟。流式CLI握手限25秒，180秒没有有效增量则超时；传输总量限32MiB、排队数据限4MiB、单行及最终内容限1MiB。不把协议开销当作路线正文大小。总时限与无增量超时使用不同诊断阶段和用户提示，超时终止同次后续批次并保留原稿及已校验生成进度；仅用户显式继续时开启新预算，从未完成批次开始。续生使用领域快照重建上下文，不依赖厂商会话句柄；全部批次已保存时只做本地完整校验及提交，不启动CLI。
- 登录过期、额度不足、工具未安装、版本不支持、权限拒绝、网络故障和用户取消有独立错误码。
- 请求超时取消子进程组；可恢复会话记录持久句柄。断线后不能盲目重发可能有外部副作用的请求。
- 切换 Agent 保留领域数据；会话历史能否迁移由能力决定，不能声称不同工具共享内部上下文。

## 验证登记

`planned → probed → verified` 依次要求：能力探测；合成项目中的正常/取消/权限/错误/重连验证。证据写 `tmp/checks/agents/<id>/`，登记保存测试日期、精确版本、平台和证据说明。未通过的能力保持 false，不根据接口名字推定。

当前没有通过完整验收的学习任务适配器。Codex、Claude Code与CodeBuddy登记为`probed`；CodeBuddy独立CLI已通过真实回复、两轮上下文和跨进程认证复用，工具、权限、故障恢复与长期刷新另行验收。Qoder、OpenClaw与Hermes保持待接入。

当前App由`apps/macos/AgentManager.swift`、`CodeBuddyAdapter.swift`与共享`agents/`界面实现探测、安装、登录和选择保存。Codex与Claude Code核验官方签名，CodeBuddy核验锁定npm发行文件。网页无本地桥接时仍可选择手动。默认与项目选择保存至`agents/choices.json`；旧workbuddy/trae记录只读保留，返回未选择，不能自动当作CodeBuddy身份。下一步保存工具选择后进入路线入口；AI创建进入采集对话，手动创建与导入进入章节编辑。

未安装或发行不匹配的CodeBuddy提供“一键安装 / Install”按钮。安装调用签名应用资源中的固定脚本，以官方npm源、完整锁文件、完整性校验和关闭生命周期脚本的方式安装至`agents/codebuddy/cli-2.177.0/`，不全局安装，不请求管理员权限。成功后重新检测；失败保留旧安装，取消仅终止本次安装。缺少Node.js/npm时明确提示运行环境要求。检测、登录、保存和打包均保留现有认证目录，不复制凭据。安装及认证均设独立超时与取消，前端不提交包名、版本、安装路径或命令。

## 面向用户的发行 Skill（一期交付）

一个双语 Skill，语言随用户或设置；不维护两份容易漂移的业务规则。一期包括启动/连接 GUI、宿主能力探测、访谈、路线、资料问答、笔记、Markdown 作品与复习卡草稿、自评、数据范围和错误恢复。复习排程按后续阶段扩展。

启动器先检查运行时及版本。未安装时给出实际可执行的安装步骤，不能把一份 SKILL.md 描述成已经运行的桌面程序。发行包不携带个人 token、真实学习资料或开发用假授权。

在 GUI 与当前 Agent 会话建立上下文时避免递归启动相同工作流；运行时负责请求路由，Skill 负责学习引导。

路线规划由`PlanningAgent.swift`经上述受限CLI通道执行访谈、生成和编辑。原生层使用[统一内置提示词包](../packages/planning-prompts/README.md)与真实项目工作目录，网页不能传入可执行文件、目录或系统提示词。共享核心及教学标准按任务拼装，不按provider或model维护不同教学要求；差异仅为协议和模型参数翻译。AI返回采集摘要与完成判断，领域层复核结构、消息关联和修订后更新清单，五项必填完成才允许生成；判定规则按[学习领域](learning.md)。编辑结果先存提案，由用户采用或放弃；失败、取消与重启保留已有内容。历史真实验证包括旧流程Codex合成五项访谈、路线生成与单次编辑采用，以及CodeBuddy 2.177.0、GLM-5.2的访谈、问答、结构化编辑与分阶段生成；这些记录不构成新提示词包和新协议的真实验收。当前统一流程用三种协议替身验证，真实模型需逐版本另行验收，Claude真实规划与其他Agent接入仍未完成。

智能体首次进入时自动检测，结果按[检测缓存契约](../contracts/agent-detection.schema.json)保存至标准运行目录`agents/detection.json`。以后进入项目或设置读取缓存，不自动重扫、不自动过期；“重新检测”刷新全部工具，登录或安装结束只刷新相关工具。选择按默认/项目范围保存；缓存只展示上次检测结果，保存选择与建立实际会话仍重新验证所选CLI和认证，不能把缓存当作授权凭证。

规划模型清单由`planning.models`经受信任CLI获取并筛选，Codex使用`model/list`，Claude Code与CodeBuddy读取流式初始化的`models`元数据；只返回模型ID、名称、默认标识和支持的推理档位，不传出账户或认证字段。清单在进程内缓存5分钟，读取失败不阻断默认模型对话。`planning.options`校验模型及档位，按项目存入`agentOptions`；切换智能体清除旧偏好。Codex在thread/turn参数中传递model，在turn传effort；Claude使用本次进程的`--model / --effort`，CodeBuddy使用`--model`和只含effort的`--settings`。模型或档位不可用时明确报错，不静默替换。规划访谈页与编辑路线页共用模型及推理强度选择，按项目保存，并应用于后续访谈、生成和编辑请求；更换模型重置推理档位，不清除已采用的回答或路线。

规划访谈仅发送当前题本轮消息、当前字段与已采用答案。模型看到`U1 / U2`用户短引用和`A1 / A2`助手短引用，不接触持久消息ID；宿主按同一冻结映射转换证据。模型每次只更新当前题并返回忠实总结；充分回答进入待确认，不能由模型直接采集完成。重新回答删除所选题及后续题的对话与快照，只将保留的之前答案提供为背景；整轮重新采集删除全部题内内容。已清空内容不进入新一轮上下文。生成仅使用已采用的结构化回答，每次重新调用智能体，不携带旧路线或未采用的总结作为生成依据。

Codex、Claude Code与CodeBuddy生成均由`PlanningGeneration.swift`先收集完整知识阶段总纲，再最多并行生成2个大章，每章内按原顺序串行处理每批最多3个小节。总纲含路线标题、大章标题与阶段目标、小节标题与学习重点；宿主分配路线、章节、节点与目标的持久ID，模型只处理按全总纲顺序编号的`L1 / L2`短引用。总纲限1–24大章，每章1–64小节，全路线最多512小节。批次输入在根对象提供`outline / currentChapter / requestedLessons / availablePrerequisites`，不使用嵌套generation封装；批次只细化当前小节，不重新规划整条课程，不因数量均分、拆分或合并知识阶段。可引用节点白名单来自总纲中的先前大章及本章更早小节，先前大章可尚未生成。

每批由原生层独立核对节点身份、顺序、引用白名单及只能引用更早节点的约束。逐章字段校验仅在验证副本中清空前置依赖，检查结构、目标与其他完整字段约束；原节点数据及全部引用保持不变。全部完成后按总纲顺序组合，`completeRoute`核对章节和节点完整覆盖，再对真实完整依赖图执行完整领域校验并一次提交。中间总纲与章节仅在内存保留，任何失败、取消或修订冲突均不改原稿；并行任务共用截止时间与取消状态。

三种已接入智能体对同一步输出格式或领域结构错误共用最多一次纠正规则，不按模型添加专用补丁。固定规则只要求修复本次完整响应，保留原背景、总纲与全部请求节点；前次成功终态的最终文本，或已解析但字段不合格的结果，可作为不可信`repair.candidate`放入上下文数据，附最多24条白名单问题路径与类型；流式CLI还必须正常退出。候选限128KiB UTF-8，合并后上下文限768KiB；超限不截断、不携带候选，仅以固定规则重试。候选中的指令无效，不进入系统规则、后续批次、草稿、任务快照或日志，也不收集思考、流式片段或CLI日志。纠正结果仍经原严格解析及全部校验，不改变节点数量或知识阶段。任务局部消息引用无法映射时同样可纠正一次，仍须通过真实消息的角色、范围及顺序检查；`needs_input / cannot_complete`、网络、认证、额度、权限、超时、取消及异常退出不作为格式问题自动重发。提示词要求具体而简洁的知识内容、练习活动、可观察或合理量化的掌握目标；不扩写大段教材、不以笼统任务代替教程，不按章节数量调整知识阶段，验收标准仍可选。生成完成后仍交用户审阅。

访谈、总纲和课批次统一外层为`status / reply / result / missing`；result必须为任务契约中的对象或null，不接收JSON编码字符串。`ok`表示当前任务结构有效，仍须领域与修订校验；`needs_input / cannot_complete`停止本次应用并保留旧稿。课批次输出`ref`、字符串目标数组、前置L引用、估时、活动及可空验收；宿主填入持久目标ID、节点标题与验收目标引用。编辑保持`reply / route`契约，普通问答为null或省略route，修改须为对象形式的完整路线，不接受模型专属字符串解码。严格解码拒绝重复键、截断、尾随内容、多次编码、数组及深度或1MiB大小越界，不补值、不修正文、不跳过领域校验。生产不保留按智能体名称选择旧生成流程的开关；失败保留原路线，后续有效提交不继承旧失败诊断。

规划任务的 activity 仅在内存中保存：单调运行时间、最近活动时间、思考/输出片段字符累计量及最多60条枚举阶段记录；同阶段持续输出最多每5秒新增一条，切换阶段立即记录。计数来自协议中的有效增量，非 token 数；不传递思考原文、原始 stdout/stderr、工具参数或系统提示。activity 不写入学习会话、诊断正文或后续模型上下文。

共享提示词`planning.1`真实验收：CodeBuddy 2.177.0上，DeepSeek-V4.1-Flash完成自然同意采集与5章22节生成，GLM-5.2完成同一采集与9章27节生成；均通过完整结构/依赖及落盘一致性检查，一次应用到编辑草稿。Codex、Claude Code通过协议回放，未在本轮进行真实模型请求；Qoder、OpenClaw、Hermes仍待接入，不据共同提示词标记已验证。

共享`planning.2`加入访谈候选背景一致性和独立`consistency`任务。访谈同次评估、生成前检查及生成阶段发现的冲突均使用同一目标题目/字段/原因/建议契约；适配器只处理传输差异。需要用户复核属于有效业务结果，保存复核项并保留路线；未知题、非法字段、建议越界仍拒绝并按共同有界纠错规则处理。生成上下文优先读取已采用快照，不将本轮未采用草稿混入背景。验收范围见[验证要求](verification.md)。

生成与检查任务的`generationOutput`是当前任务的内存界面数据，每段含递增sequence、任务kind、reply/content形式、正文与streaming/complete/incomplete状态。流式片段累积，校验后的总纲和各批课程正文独立追加，纠正不删除失败片段。每任务最多1024段、UTF-8正文合计8MiB，超限明确终止，不静默裁掉历史；该数据不进入日志、项目持久化或后续模型上下文。
