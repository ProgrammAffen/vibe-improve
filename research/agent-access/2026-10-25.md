# 智能体图标与 CLI 接入

- 日期：2026-10-25
- 状态：部分待验证
- 适用范围：macOS arm64；Codex CLI 0.163.0-alpha.11.1、Claude Code 2.1.209；其余工具为官方接口调研。
- 调研问题：七款真实图标、本机可交互性、创建与设置的共享接入入口。

## 结论

事实：七款图标均已收集，Codex、Claude Code 从官方签名应用中原样提取，其余从官网或官方 CDN 获取。来源、尺寸、SHA-256 与待审阅标记见图标清单（历史临时材料已清理：`../../tmp/review/2026-10-25-agent-access/icon-sources.json`）。48px 原件适合列表，不应放大成主视觉。官网可下载不等于获得任意品牌使用授权，当前用途为工具身份识别，原件未改色或重绘。

本机通过签名核验、版本与帮助命令确认两款 CLI：Codex 位于官方应用内，Claude Code 位于 Claude 桌面应用下载的版本目录。PATH 中另一个同名 codex 的来源不同，未执行，不能以命令名认定为 OpenAI CLI。TRAE、Qoder、WorkBuddy、OpenClaw、Hermes 未在约定范围发现，用户确认尚未安装；没有进行模型对话测试。

Codex 的官方登录状态接口返回已登录；最小CLI对话已通过：`codex exec`返回指定随机短标记，进程退出0，并取得thread/turn开始、消息完成与turn完成事件。SQLite、日志与临时目录位于仓库。测试需要以读写方式打开原有 installation_id，用户已明确允许这一文件；执行前后哈希一致、内容未改变。其余仓库外写入仍被阻止，快照与插件缓存的附属写入警告没有阻止本次文本响应。首次受限尝试与最终结果保留在tmp，不以警告推断其他功能可用。

Codex app-server stdio 的 `initialize → initialized → account/read` 也已通过，认证类型为ChatGPT；仅保留状态，不保存账号邮箱或令牌。这证明CLI的基本协议通道可用，不代表GUI适配已完成。

Claude Code 的官方认证接口返回 `loggedIn=false`、`authMethod=none`。最小无工具请求没有返回目标响应；需要用户在 Claude Code CLI 完成登录后再测。Claude 桌面应用存在不代表 Claude Code 认证已就绪。

Claude Code官方支持 `auth login` 发起浏览器认证，`auth status --json`供应用查询状态。本机2.1.209的登录帮助已核验；未启动真实登录或替用户完成授权。登录检测与“去登录”按钮可以由桌面壳封装。默认不加 `--console`，因为该选项切换到Console/API计费。命令依据见[CLI参考](https://code.claude.com/docs/en/cli-reference)，浏览器授权与终端回填依据见[认证说明](https://code.claude.com/docs/en/authentication)。此流程尚未应用到App。

没有一款生产适配器完成正常、权限、取消、错误和重连的全套验收；两款已探测工具为 `probed`，能力登记不标为 `verified`。

## 未确定事项

- Codex最小模型响应通过；增量流式、权限往返、取消、恢复、多轮与GUI适配尚未完成。
- Claude Code 登录后实际模型响应、流式、权限与取消：CLI未登录。
- 其余五款的安装版本、认证、模型配额、会话恢复、取消与MCP：没有本机证据。
- 官方应用内置路径可能随更新变化；正式发现流程须重新解析来源，不锁死本次个人路径。
- CLI能对话不保证请求出现在厂商桌面应用；桌面同步只在官方明确支持且实测后登记。

## 对开发的影响

创建页采用第3种黑板连接台。名称与目录后检测；设置一级分类增加智能体，复用相同检测和连接组件，允许手动项目随时补连。探测不发模型请求，连接与实际测试分开；当前检查结果不固化进产品。安装、认证、协议与对话状态独立，默认工具、项目选择和会话句柄分开保存。执行边界见[Agent契约](../../harness/agents.md)，界面见[体验规范](../../harness/experience.md)。
