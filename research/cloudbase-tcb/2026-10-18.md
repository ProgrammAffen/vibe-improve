## 账号接口

| 功能 | 官方 SDK 入口 | 集成要求 |
| --- | --- | --- |
| 邮箱密码登录 | `auth.signInWithPassword({ email, password })` | 环境启用密码登录；错误与网络失败分别处理 |
| 注册发码 | `auth.signUp({ email, password })` | SDK 是智能注册/登录语义，不能假定已存在邮箱必报重复注册 |
| 注册确认 | 返回的 `data.verifyOtp({ token })` | 该闭包绑定本次发码 ID；不要与独立 `verifyOtp` 的参数规则混用 |
| 忘记密码发码 | `auth.resetPasswordForEmail(email)` | 仅为已注册邮箱完成恢复 |
| 找回确认 | 返回的 `data.updateUser({ nonce, password })` | 成功后产品会话撤销并重新登录 |
| 旧密码改密 | `auth.resetPasswordForOld({ old_password, new_password })` | 该方法本身没有邮件验证码步骤 |
| 邮件二次验证改密 | `auth.reauthenticate()` → `data.updateUser({ nonce, password })` | 要保留参考库“旧密码+验证码”，使用已核实 HTTP 接口组合并联调 |
| 当前账号/退出 | `auth.getUser()` / `auth.signOut()` | 产品会话和 license 仍独立维护 |

SDK 当前使用统一 `@cloudbase/js-sdk` v3。界面文案不直接显示 SDK 内部错误。密码更新不走资料接口 `updateUser`。[官方 SDK 认证](https://docs.cloudbase.net/api-reference/webv3/authentication)

3.10.2 的发布类型支持 `persistence: 'none'`，但发布 source map 显示 OAuth adapter 仍默认使用 localStorage。内存会话必须在 `app.auth` 配置传入独立内存 `storage`，实现异步 `getItem/setItem/removeItem` 与同步 `getItemSync/setItemSync/removeItemSync`，同时指定 persistence。桌面由原生文件适配器单独加密持久化会话令牌，浏览器存储仍不写令牌。[官方 npm 发布包](https://registry.npmjs.org/@cloudbase/js-sdk/-/js-sdk-3.10.2.tgz)

邮箱验证码支持平台邮件代发，无须自备 SMTP；配置入口是身份认证→登录方式→邮箱验证码→配置发件邮箱→开启邮件代发。CLI `env login set --email-login true --username-login true` 只开登录策略，不等于已配置发件邮箱。Manager SDK 5.1+ 可先 `app.env.getProviders()` 取得 EMAIL 身份源 ID，再增量 `modifyProvider({ Id, ProviderType: 'EMAIL', On: 'TRUE', EmailConfig: { On: 'TRUE' } })` 启用默认代发；具体环境仍需真实送达验证。[邮箱配置](https://docs.cloudbase.net/authentication-v2/method/email-login)、[Manager 登录配置](https://docs.cloudbase.net/api-reference/manager/node/login-config)

对无状态云函数，SDK 返回的回调闭包不能跨实例保存为挑战记录。可选前端 SDK 完成身份流程，或业务层封装以下身份认证 HTTP API。选定后锁定单一路径，不交叉使用不同发码 ID。

| HTTP 接口 | 已核实用途 |
| --- | --- |
| `POST /auth/v1/verification` | 邮箱发码；`target: ANY` 用于注册/登录，`USER` 用于现有账号；响应有 `verification_id` |
| `POST /auth/v1/verification/verify` | 传入本次 ID 与验证码，返回 `verification_token` |
| `POST /auth/v1/signup` | 邮箱、验证 token、密码及可选昵称注册 |
| `POST /auth/v1/token` | 刷新令牌；刷新后持久化替换令牌 |
| `POST /auth/v1/user/reauthenticate` | 已登录账号请求邮箱二次验证码 |
| `PATCH /auth/v1/user/password` | Bearer 身份、旧/新密码和 `verify_code` 改密 |

HTTP 基址形式为 `https://<envId>.api.tcloudbasegateway.com`。邮箱密码登录的 SDK 适配和密码恢复 HTTP 字段必须按锁定版本源码/契约验证，不能从旧版 `username` 文档猜测邮箱映射。[发码](https://docs.cloudbase.net/http-api/auth/auth-send-verification)、[验码](https://docs.cloudbase.net/http-api/auth/auth-verify-verification)、[注册](https://docs.cloudbase.net/en/http-api/auth/auth-sign-up)、[刷新](https://docs.cloudbase.net/http-api/auth/auth-grant-token)、[二次验证](https://docs.cloudbase.net/http-api/auth/user-reauthenticate)、[改密](https://docs.cloudbase.net/http-api/auth/user-update-password)

本机 CLI 3.2.2 的 `login` 会先检查认证，未登录即进入授权；部分资源命令也会自动触发认证。它不是无副作用的 `whoami`。源码存在 `~/.config/.cloudbase` 目录初始化，嵌套依赖部分不读取 `XDG_CONFIG_HOME`。为满足仅在工作区写文件，项目包装器必须将 CLI 的配置/缓存/日志隔离至 `tmp/runtime/`，不得只设置 XDG 后假定全局不写。不要把已有全局凭据复制到仓库或打印出来。

## 数据库与权限

服务端 `@cloudbase/node-sdk` 支持事务，事务中仅按确定文档 ID 读写，不使用 `where`；不把发邮件或外部请求放入事务。兑换码占用、权益签发、设备席位和幂等记录必须原子提交。[事务](https://docs.cloudbase.net/database/transaction)

锁定数据库包 1.4.3 的 `src/document.ts` 进一步确认：事务 `doc.get()` 的 `data` 是单对象或 `null`；普通 `doc.get()` 的 `data` 是数组。返回 `code` 是失败，不能视为不存在。`runTransaction(callback)` 直接返回回调结果，冲突重试会再次执行回调；事务 `set/update` 接收字段平对象。[官方数据库发布包](https://registry.npmjs.org/@cloudbase/database/-/database-1.4.3.tgz)

事件函数身份以 `app.auth().getAuthContext(platformContext).uid` 为来源，第二参数只能是平台传入的真实上下文。`getUserInfo()` 仅读进程环境，不能强制它与 context 的 UID 同步存在。`getCloudbaseContext(platformContext)` 可读取匿名标记，但也含云端凭据，只提取需要的字段，禁止整体记录或返回。`getClientIP()` 不是身份验证；公开 HTTP Server 必须另行验证令牌。普通合成邮箱账号已通过已部署事件函数的可信身份检查；未知身份继续拒绝，不从成功调用推测其他未观察的 LOGINTYPE 枚举。[官方 Node SDK 发布包](https://registry.npmjs.org/@cloudbase/node-sdk/-/node-sdk-3.18.3.tgz)、[官方鉴权源码](https://github.com/TencentCloudBase/node-sdk/blob/master/src/auth/index.ts)

管理员可用 Manager Node SDK 创建集合。账号业务集合禁止普通客户端直连读写；云函数验证身份与归属后访问。数据库权限规则和函数调用权限不是同一配置。[集合管理](https://docs.cloudbase.net/api-reference/manager/node/database)、[数据库安全规则](https://docs.cloudbase.net/database/security-rules)、[函数权限](https://docs.cloudbase.net/cloud-function/security-rules)

## 桌面登录保持

锁定SDK的setSession会在线刷新令牌并返回会话，不是只填充本地缓存；getSession读取当前会话，TOKEN_REFRESHED事件用于更新轮换结果。桌面保留SDK内存storage，单独以受信异步桥保存access/refresh令牌到运行时固定加密文件，v2记录未到期时经已配置的内存storage恢复，按期限刷新；v1记录或到期token使用setSession在线刷新。源码核实自3.10.2发布source map。[认证API](https://docs.cloudbase.net/api-reference/webv3/authentication#setsession)

macOS原生文件适配器使用CryptoKit的AES-256-GCM、随机32字节本地密钥与12字节nonce，原子写入应用同级的运行时目录，无系统凭据库依赖。目录0700、文件0600；启动仍必须向CloudBase验证。共享认证生命周期与加密文件格式可供Windows适配，当前Windows原生壳未实现。格式及本地保护范围见[登录保持](../../harness/license.md)。

3.10.2的OAuth LocalCredentials使用 `credentials_<clientId>` 读写凭证，clientId未显式指定时使用env；`expires_at` 以Date解析，未过期时getAccessToken直接返回本地access token。已用真实 `@cloudbase/js-sdk/oauth` 和自定义storage验证有效token读取为零网络请求，不调用SDK私有方法。最小显示信息与授权缓存另在加密记录保存；正向授权恢复仍验Ed25519签名与签名租约。登录固定7天、提前60秒刷新、负向状态缓存5分钟是本应用策略，不是CloudBase默认配置。[认证API](https://docs.cloudbase.net/api-reference/webv3/authentication#getsession)
